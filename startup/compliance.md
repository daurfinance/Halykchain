## 1. Правовая база

| НПА | Что важно для нас |

| Закон «О разрешениях и уведомлениях» | Перечень лицензируемых видов — расследования/OSINT/ИБ-консалтинг в него не входят (кроме СКЗИ и др.) |

**следим за законопроектами**, при принятии оцениваем необходимость лицензии.

## 2. Допустимые методы

- открытые государственные реестры и публичные сервисы;
- опубликованные судебные акты и сведения об исполнительных производствах;
- СМИ, публичные страницы в соцсетях (без обхода настроек приватности, без фейковых «дружб»);
- коммерческие базы данных, законно работающие в РК/за рубежом, с проверкой их законности;
- информация, предоставленная клиентом или субъектом добровольно;
- исследование систем клиента — только по письменному договору с их владельцем.

## 3. Недопустимые методы

- любые ОРМ-подобные действия: негласное наблюдение, прослушивание, контроль корреспонденции;
- претекстинг с представлением сотрудником госоргана, банка, оператора связи;
- использование слитых баз, «пробивщиков», инсайдеров в госорганах/банках/телеком;
- доступ к аккаунтам и системам без разрешения владельца;
- спецтехника негласного получения информации;
- распространение собранных сведений третьим лицам сверх заказчика.

## 4. Персональные данные

1. **Политика обработки ПДн** — утверждается приказом, публикуется на сайте.
2. **Ответственный за ПДн** — назначается приказом.
3. **Основания обработки** для каждого заказа фиксируются в карточке дела:
   - согласие субъекта (People Screening — обязательно, письменное);
   - общедоступные ПДн;
   - исполнение договора / законный интерес заказчика — только в пределах, допустимых законом (проверяет юрист).
4. **Минимизация:** собираем только то, что нужно для цели заказа.
5. **Хранение:** материалы дела — не дольше 12 месяцев после сдачи отчёта (если иное не требует закон), затем удаление с актом.
6. **Локализация:** базы с ПДн граждан РК — на серверах в РК.
7. **Права субъектов:** порядок ответа на запросы о доступе/удалении.

## 5. Intake-процедура (до начала любой работы)

Чек-лист заполняет аналитик, утверждает руководитель; при любом «нет»/«неясно» — юрист.

- [ ] Заказчик идентифицирован (юрлицо: БИН, подписант с полномочиями; физлицо — только по согласованию с юристом)
- [ ] Цель заказа указана и законна (сделка, трудоустройство, взыскание, защита систем…)
- [ ] Объект: юрлицо / физлицо / система клиента
- [ ] Для физлица есть согласие или подтверждённое законное основание
- [ ] Для ИБ-работ есть подтверждение, что заказчик — владелец системы или имеет полномочия
- [ ] Запрошенные методы — только из раздела 2
- [ ] Нет признаков преследования, давления, рейдерства, семейных споров «найти/проследить»
- [ ] Нет конфликта интересов с текущими клиентами
- [ ] Договор и, при необходимости, NDA подписаны

## 6. Внутренние документы для запуска

1. Устав ТОО с ОКЭД 80.30, 62.02, 62.09, 63.99, 70.22.
2. Политика обработки и защиты ПДн.
3. Кодекс этики и допустимых методов (публичный).
4. Положение о коммерческой тайне и NDA сотрудников.
5. Регламент intake и ведения дел.
6. Регламент пентеста (Rules of Engagement) и форма разрешения на тестирование.
7. Политика ИБ самой компании (доступы, шифрование, журналирование, удаление).
8. Шаблоны договоров — см. [contract-template.md](./contract-template.md).
9. Форма согласия субъекта на проверку (People Screening).

## 7. Налоги и учёт — вопросы к бухгалтеру

- выбор режима (упрощённая декларация / общеустановленный) с учётом лимитов;
- постановка на учёт по НДС при превышении порога или по желанию (крупные клиенты предпочитают НДС-плательщиков);
- возможность резидентства Astana Hub для SaaS-направления;
- формулировка предмета услуг в договорах и актах **строго по фактическому содержанию**.
